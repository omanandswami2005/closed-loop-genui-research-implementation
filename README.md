# Learner-State-Aware Generative User Interfaces

A closed-loop control architecture for adaptive learning interfaces, applied to
multi-step linear equations (ax + b = c). Bayesian Knowledge Tracing estimates
mastery, a PID governor turns it into a structural complexity budget M_I*, a
fast policy picks the scaffolding, a generative plant (Gemini 3.7 Flash, or a
deterministic surrogate) emits a JSON interface tree, and a validation gate
admits it or renders a fallback template. All evaluation is in silico; there
are no human-subject results.

**Live demo:** https://genui-xri32xbnma-uc.a.run.app (may be offline)

## Requirements

Python 3.11 or newer, Node 22 or newer. The real Gemini plant also needs access
to the Google Cloud project (see below); everything else runs offline.

## Run the app locally

```
cd backend
pip install -e ".[service]"
uvicorn closedloop.service:app --port 8000
```

In a second terminal:

```
cd frontend
npm install
npm run dev            # open http://localhost:5173
```

Pick the **surrogate** plant to run fully offline. The **gemini** plant calls
Vertex AI; locally, pass a token from your own Google account:

```
GENUI_GEMINI_TOKEN=$(gcloud auth print-access-token) uvicorn closedloop.service:app --port 8000
```

If Gemini is unavailable for any reason (no token, billing, quota or the daily
cap), the item is generated by the surrogate plant and the page shows a short
notice instead of an error.

## Run the tests

```
cd backend && pip install -e ".[test]" && python -m pytest
cd frontend && npx tsc -b
```

## Run the 1,000-learner benchmark

```
cd backend
pip install -e .
python -m closedloop.sim.run --out ../results/benchmark
```

Takes about a minute on 4 cores. It simulates 1,000 synthetic learners (300
struggling novices, 400 inconsistent guessers, 300 fast masters, 40 items
each, seed 20261003) through the 4 arms (static, unconstrained GenUI,
rule-based, closed loop), 3 ablations and the lapse-handling extensions.
Results land in `results/benchmark/`: `summary.csv` is the main table, and
`manifest.json` records every parameter. The file list is in
[backend/README.md](backend/README.md#outputs-resultsbenchmark).

Related runs, all from `backend/`:

| Command | Output |
|---|---|
| `python -m closedloop.sim.tune search --out ../results/tuning` | controller tuning (`tuning.json`, `search.csv`) |
| `python -m closedloop.sim.tune sensitivity --out ../results/tuning` | parameter and M_I weight sensitivity |
| `pip install -e ".[laya]" && python -m closedloop.sim.laya_eval --out ../results/laya` | real Laya policy vs the surrogate |

## Run the real Gemini measurement

The measurement sends interface requests to `gemini-3.7-flash` on Vertex AI
and scores every answer with the same validation gate as the benchmark. It
spends Google Cloud credits (about $2 for 300 calls).

**From GitHub Actions (recommended, no keys needed):** open the repository's
**Actions** tab, choose **Gemini plant measurement**, click **Run workflow**
and set the number of calls (default 300). When the run finishes, download the
`gemini-results` artifact; it holds `summary.json` and `calls.csv`. To update
the committed numbers, copy them into `results/gemini/` and commit.

**Locally:**

```
cd backend
pip install -e ".[service]"
GENUI_GEMINI_TOKEN=$(gcloud auth print-access-token) python -m closedloop.sim.gemini_eval --out ../results/gemini --n 300
```

The committed run is in `results/gemini/` (`summary.json` and one row per call
in `calls.csv`).

## Deployment

Every push to `main` that changes the app rebuilds one container (frontend and
service together, `Dockerfile`) and deploys it to Cloud Run in project
`omni-505707`, region `us-central1` (`.github/workflows/deploy.yml`). GitHub
Actions authenticates with Workload Identity Federation, so no key is stored
anywhere. The service scales to zero when idle and runs at most one instance
(sessions live in memory). Live Gemini use is capped at 200 calls per day in
total and 3 Gemini sessions per visitor IP per hour; past either limit the
surrogate plant takes over. `infra/gcp/bootstrap.sh` recreates the cloud setup
from scratch.
